# 产品说明（Product Brief）

名称：funnel-analytics-miniprogram

形态：微信原生小程序 + 小程序·云开发（serverless，无自建服务器）

架构：`miniprogram/` 前端 + `cloudfunctions/` 云函数 + 云数据库

## 设计原则

**数据不足时拒绝给结论，绝不猜。** 这条原则统一裁决所有边界情况，目前已经落到五处：导入时阶段名匹配不上就报错、不按位置对齐（Q5）；表格方向不自动判断、转置必须由用户触发（Q8）；空白单元格视为缺失而不是 0（Q9，见 `docs/adr/0004-atomic-import-reject-blanks.md`）；凑不齐一个完整周期就不算环比（Q12）；数据不足以构成窗口就不产生异常点（`docs/adr/0005-rule-based-anomaly-detection.md`）。后续遇到新的边界情况，默认按这条原则处理，除非有明确理由破例，且破例必须写进 ADR。

## 已确定的约束

- **通用档位：半通用。** 数据模型与计算引擎按通用设计（阶段用数组存）；使用者从 3 个内置模板出发创建漏斗，不能面对空白编辑器从零自建。
- **模板：** 三套，作为阶段与顺序的默认起点（创建时可增删）：运营 `曝光→点击→注册→激活→留存`；销售 `线索→跟进→报价→成交`；教培 `试听→报名→到课→续费`。其中「运营」特指内容/增长型运营，不含电商运营——电商模板属于后续迭代（纯内容新增，不动结构）。
- **阶段：** 每个漏斗 3–7 段。**创建时可基于模板增删**（此刻没有历史数据，调整不付代价），**创建后锁定**，只能改名；同一漏斗内名称唯一。
- **修订记录：** Q22 修订了 Q1/Q3 的原始边界——原为「阶段集合完全固定、只能改名」，现改为「创建时可增删、创建后锁定」。
- **阶段身份是双轨的：** 存储与对齐用下标，导入匹配用名称（名称在同一漏斗内唯一）。两者不能混用——匹配失败必须显式报错，绝不允许静默退化为按位置对齐。
- **数据口径：** 聚合人数（阶段 × 日期），不做跨阶段去重，转化率是人数之比。理由与后果见 `docs/adr/0001-aggregated-daily-counts.md`。
- **数据归属：** 按微信用户隔离（`_openid` + 仅创建者可读写）。云函数以管理员身份运行、会绕过安全规则，写入时必须显式补 `_openid`。见 `docs/adr/0003-per-user-data-isolation.md`。
- **录入格式：** 从剪贴板读取制表符分隔的纯文本；行 = 日期、列 = 阶段（首列为日期，表头为阶段名）。另提供一键转置按钮，兼容行列为反方向的表；转置由用户主动触发（解析失败时提示），**绝不自动判断方向**。
- **导入策略：** 原子导入——任何一处不合法则整批拒绝，并一次列全所有问题位置（不是报第一个就停）。解析只做无损规范化：去首尾空格、全角转半角、去掉千分位逗号。**空白 = 缺失，绝不等于 0。** 见 `docs/adr/0004-atomic-import-reject-blanks.md`。
- **日期解析：** 接受 `2025-05-01`、`2025/5/1`、`2025年5月1日` 并规范化为同一格式；**无年份的一律拒绝**（跨年时补全年份必然无声出错）；同一批里出现重复日期则整批拒绝（两个矛盾的值无法判断哪个对）。日期**不要求有序、也不要求连续**。
- **入口人数呈现：** 与折线图上下并列的小型趋势柱状图（横轴为窗口内日期，纵轴为第一阶段人数），不用汇总卡片——入口人数的价值在趋势。
- **口径声明：** 漏斗详情页整体转化率数字下方一行浅色小字「口径：各阶段人数之比，不做同批人去重」。D2 要求这条口径必须在产品内可见，位置紧跟最容易被误读的那个数字。
- **转化率口径：** 每个阶段显示**逐步转化率**（本阶段 ÷ 上一阶段，第一阶段为基准 100%）；页面顶部单独显示**整体转化率**（末阶段 ÷ 首阶段）。不做「每个阶段都挂两个百分比」。
- **除零显示：** 上一阶段 > 0 且本阶段 = 0 → 显示 `0%`（真实结论）；上一阶段 = 0 → 显示 `—`（不可计算）。其中「上一阶段 0 人但本阶段 > 0 人」额外标记为**矛盾数据**。
- **环比口径：** 窗口长度由使用者在 7 / 14 / 30 天中选择，默认 7 天；数据不足以凑齐一个完整周期时，环比显示 `—`。
- **异常检测：** 规则式（环比阈值），不做统计式检测；监控对象只有**各步逐步转化率**与**入口人数**两类，中间阶段的绝对人数不单独监控；数据不足一个完整窗口时明确显示「数据不足，暂不判定」。见 `docs/adr/0005-rule-based-anomaly-detection.md`。
- **异常门槛：** 相对阈值默认 **30%**（两个指标共用）；参与判定的样本量低于 **20** 时不判定，显示「样本过小，暂不判定」。两个数值都是初始猜测值，必须写成集中的具名常量，上线后用真实数据校准。
- **读写分工：** 读取由小程序端直查数据库、计算全在前端；只有**写入**走云函数。前置条件：`funnels` 与 `records` 的权限规则必须是「仅创建者可读写」。见 `docs/adr/0006-client-reads-cloud-writes.md`。
- **折线图：** 默认显示**整体转化率**一条线，可切换到任一步的**逐步转化率**；不做多线叠加。**入口人数不画进这张图**（量纲不同，共轴会互相失真）。
- **异常标注：** 只在异常发生的那一天在折线上打点；图表上方给一行**跨图表**的异常摘要（注明是哪个指标、偏离多少），因为入口人数不在这张图上；每个异常点可点开查看判定依据（「较上期下降 42%，超过 30% 阈值」）。
- **漏斗图：** 经典梯形漏斗，宽度**严格按人数比例，不设最小宽度**。明知极端数据下末段会缩到近乎不可见，仍然选择不美化形状——这是有意的让步：形状只负责说真话，数字由标签负责。标签采用内嵌 + 侧置混合：宽段内嵌居中，窄段移到同一水平线的两侧空白区与该段垂直对齐，无需引导线（梯形上宽下窄，越靠下的段两侧空白越大，空间与需求正好反向）。人数为 0 的阶段宽度为 0，但用**极细虚线**标记其存在，避免把"这一段断了"和"图没画出来"混为一谈——注意这与最小宽度性质不同：最小宽度是假装数值更大（失真），0 值标记不对数值做任何声张。
- **时间轴锚点：** 锚在**最新一条记录的日期**并向前推窗口长度，不锚在今天（使用者的数据最新日期几乎不会是今天，锚在今天会让图表大部分时候空着）。**禁止省略中间空缺把不相邻的日期连成相邻点**——那是编造趋势。展示范围与环比窗口是同一个参数。轴上必须显式标注起止日期，因为锚点不是今天。
- **数据跨度：** 导入**不限天数、全部保存**；图表展示受窗口上限约束（最多 30 天）。导入成功后必须明确告知「已保存 N 天，当前展示最近 M 天」——存了 90 天却只能看 30 天而不说明，使用者会认定数据丢了。不采用"限制导入为 60 天"的方案，因为截断不可逆，而多存数据的代价几乎为零（一年 365 条文档）。

## MVP 功能边界

**进 MVP：**

1. 漏斗列表（首页）：列出已保存的漏斗、进入某个、新建入口。
2. 新建漏斗：选模板 → 调整阶段（增删至 3–7 段、改名）→ 命名 → 创建。
3. 漏斗详情：整体转化率 + 7/14/30 切换 + 异常摘要行 + 梯形漏斗 + 折线图（可切换指标）+ 入口人数独立呈现。
4. 导入数据：粘贴 → 原子校验（一次列全问题）→ 预览 → 确认入库。
5. 漏斗管理：重命名漏斗、改阶段名、清空该漏斗全部数据、删除漏斗。

**排除到后续迭代：** 单日数据删除/编辑、导出图片或数据、多漏斗对比、电商模板、自定义异常阈值、分享与协作、创建后修改阶段结构。

**两条边界判断：**

- 单日删除不做，用「重贴覆盖 + 清空全部」兜底。写入是按「漏斗 + 日期」覆盖，所以"贴错了改对"这条路径天然通畅；单独为"这一天我不要了"做一套记录管理界面，是 MVP 里性价比最低的一块。
- 「清空全部数据」**必须进 MVP**。它是唯一的逃生舱：一旦导入整批错位数据、或拿错模板建了漏斗，没有它就只能删掉漏斗重建。实现成本几乎为零（一条按漏斗删除的云函数）。
