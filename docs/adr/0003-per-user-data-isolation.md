# 数据按微信用户隔离，云函数必须自行补齐 `_openid`

每个使用者只能读写自己创建的漏斗与记录。客户端创建的文档由云开发自动写入 `_openid`，把安全规则设为「仅创建者可读写」即可；云函数以管理员身份运行、会**绕过**安全规则，因此由云函数写入的文档必须显式带上从 `cloud.getWXContext()` 取得的 `_openid`，读取时也必须带上同样的过滤条件。

## Considered Options

- **所有人共享**：不需要任何鉴权代码，但漏斗数据（线索量、成交率、续费率）是使用者最敏感的经营数据，共享意味着任何人打开小程序就能看到别人企业的经营指标。
- **组织内共享**：需要自建组织、邀请与成员管理，属于另一个产品范围。

## Consequences

- 云函数里每次读写都必须自己带 owner 过滤条件。漏写不会报错，而是静默地返回或覆盖全库数据——这是最难发现的一类缺陷，必须靠专门的回归用例覆盖「A 用户读不到 B 用户的数据」。
- 后续若要做团队共享，不能只在安全规则上放开：必须补出组织与成员概念，并迁移既有文档的归属字段。
