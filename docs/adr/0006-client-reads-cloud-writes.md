# 读取走客户端直查、计算在前端，只有写入走云函数

`funnels` 与 `records` 的读取由小程序端直接查询数据库，转化率、环比、异常判定等计算全部在前端完成；云函数唯一的职责是写入（原子导入）。前置条件是两个集合的安全规则都必须设为「仅创建者可读写」。

## Considered Options

- **读写与计算全部走云函数**（CloudBase 更常见的写法）：能绕过小程序端单次 20 条的查询上限。但云函数以管理员身份运行，必须自己带 owner 过滤条件——一旦漏写就变成读到其他用户的数据（fail open）。
- **云函数取数、前端计算**：同样失去 fail-closed 性质，换来的只是不用翻页。

## Consequences

- 云函数漏写 `_openid` 时，症状是"读不到自己的数据"（fail closed），一测就暴露；而不是静默读到别人的数据（fail open）。同一个疏漏，两种失败方式的代价相差一个数量级。
- 读取路径与业务口径分离：将来数据量上来，把读取挪到云函数不需要改动任何计算代码。
- 代价：小程序端单次查询上限 20 条，30 天视图需翻 2 页、90 天需翻 5 页；默认的 7 天视图一次请求足够。
- 写入必须留在云函数：小程序端没有事务和批量写，ADR-0004 要求的原子导入只有 `db.runTransaction` 能保证。
