# 导入是原子的：任何一处不合法整批拒绝，空白不等于 0

一次粘贴要么整体写入，要么整体不写入；校验会一次性列出所有问题位置，而不是遇到第一个就停。解析时只做无损规范化（去首尾空格、全角转半角、去掉千分位逗号）；空白单元格视为「缺失」并导致整批拒绝，绝不会被当作 0。

## Considered Options

- **部分入库**：合法的日期行先保存，有问题的行跳过。使用者会看到"保存成功"，却不知道有若干天没进去，从而把数据断层误读成真实下跌。
- **尽力修正**（空白补 0、缺日期按顺序补）：会产生看起来正常、实则错误的数据，而且这类错误永远不会被使用者发现。

## Consequences

- 数据库里不存在"部分导入"的中间状态，也永远不会出现含义不明的 0。
- `records` 的 `counts` 中每个元素都是使用者显式填写的实测值，可以无条件信任。
- 代价是使用者可能要来回粘贴几次。缓解手段是校验一次列全所有问题，而不是报第一个就停。
- 将来若要允许空白单元格，不能只放开校验：必须先决定「缺失」在 `counts` 数组里如何表示（`null`、独立字段，还是干脆不入库），并重新解释历史数据中已有的 0。
