# 漏斗数据以「阶段 × 日期」的聚合人数存储，不采集用户级明细

漏斗的最小数据单位是某个漏斗在某一天、某个阶段的人数，由使用者粘贴汇总表录入。系统不做跨阶段去重，因此「转化率」是各阶段独立人数之比，而不是同一批人的转化率。

## Considered Options

- **用户级事件流水**：能算出严格的同批人转化、路径回溯和单用户诊断，但要求使用者拿得到用户级明细，且云函数需要处理去重与时间窗口计算。对 MVP 而言成本不成比例。
- **两种都支持**：等于把事件级的复杂度提前引入，与半通用档位（模板固定、只改名称）不匹配。

## Consequences

- 无法回答「同一批人」的转化、路径回溯、单用户诊断这类问题。
- 转化率口径必须在产品说明里显式声明，否则使用者会把它当严谨报表使用。
- 好处是数据结构简单：聚合人数可直接映射为云数据库文档，导入校验只需要检查数字。
